# はてな痕跡の除去 (de-hatena) 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** はてなへの技術的依存 (URL 名・alt 記法・Worker フォールバック・移行ツール) をすべて除去し、画像はローカル `/blog-images/`、CLS は rehype による寸法注入で解消する。

**Architecture:** 画像実体は `git mv` で改名し、markdown は URL 接頭辞の置換のみ (標準記法維持)。Worker ははてな CDN を参照するコードを消して旧 URL 向けの 301 を 1 箇所追加。寸法はビルド時 rehype プラグインで生成 `<img>` に注入。lint/format は Vite+ (`vp check`)、ビルドは Astro のまま。

**Tech Stack:** Astro 7.2.9 (内部 Vite 8.1.0) / Cloudflare Workers + Static Assets / vite-plus 1.1.0 / sharp / bun

**Spec:** `docs/superpowers/specs/2026-10-10-de-hatena-design.md` (決定済み。本計画はこれを実装する)

## Global Constraints

- AGENTS.md 準拠: 各変更後は `bun run lint` → (`bun run format` で差分が出たら適用) → `bunx astro check` → `bun run build` の順に検査する
- コミットメッセージは Conventional Commits + 日本語。本文 (body) に「Why」を書く
- `.env` の内容は絶対にコミット・表示しない
- git 操作は本計画の実行開始承認をもって指示とする (spec「前提の確認事項」)。計画外の git 操作はしない
- 画像の実体は `public/blog-images/` を唯一の正とする。旧 `/hatena-images/` 文字列は Worker の redirect 条件 1 箇所にのみ残す
- markdown は `![alt](url)` 標準記法を維持する (HTML に書き換えない、寸法を md に埋めない)

## Review Focus

- **旧 URL の完全除去**: `dist/**/*.html` に `/hatena-images` / `f:id:` / `cdn-ak.f.st-hatena.com` が一切残らないこと (Task 7 で全数 grep)。301 を張った理由は「壊さず受ける」であって「残してよい」ではない
- **rename と md 変換の一致性**: `public/blog-images/` の 897 ファイルと md 参照 895 点が全点対応すること (Task 4)。点数がずれたら上書き/欠落がないか確認する
- **alt 空化の正確性**: `![f:id:...](...)` だけを対象にし、本文中の `f:id:` (はてな ID 参照は md に 1,361 件ある) とコードブロック内の例を壊さないこと (Task 4)
- **Worker の 301**: `/hatena-images/*` を canonical 補正より先に受けて、apex + `/blog-images` へ 1 ジャンプで転送すること。クエリ文字列が消えないこと (Task 3 の smoke で検証)
- **rehype プラグイン依存の最小性**: 新しいランタイム依存を追加せず、unified/hast の型はローカルで定義する (Task 5)

```ts
const CANONICAL_HOST = "bunkei-programmer.net";
const WWW_HOST = "www.bunkei-programmer.net";
const LEGACY_IMAGES_PREFIX = "/hatena-images/";

export default {
  async fetch(request: Request, env: Env) {
    const url = new URL(request.url);

    // はてな時代の画像 URL (/hatena-images/*) を新 URL に 301 で受ける。
    // Why not: 404 にするのは外部リンク・ブックマーク・検索インデックスを

      url.hostname = CANONICAL_HOST;
      url.pathname = url.pathname.replace(/^\/hatena-images/, "/blog-images");
      return Response.redirect(url.toString(), 301);
    }

    if (url.protocol !== "https:" || url.hostname === WWW_HOST) {
      return redirectToCanonical(request);
```

```ts
// What: md 内の /hatena-images/ パスを /blog-images/ に置換し、
//       画像構文 (![](url)) の alt に f:id: 記法が来ているものだけを空 alt にする。
import { readdir, readFile, writeFile } from "node:fs/promises";
import path from "node:path";

const CONTENT_DIR = "src/content/blog";
const OLD_PREFIX = "/hatena-images/";
const NEW_PREFIX = "/blog-images/";

async function collectMd(dir: string): Promise<string[]> {
  const out: string[] = [];
  for (const entry of await readdir(dir, { withFileTypes: true })) {
    const full = path.join(dir, entry.name);
    if (entry.isDirectory()) out.push(...(await collectMd(full)));
    else if (entry.isFile() && entry.name.endsWith(".md")) out.push(full);
  }
  return out;
}

let touched = 0;
let pathReplaced = 0;
let altCleared = 0;

for (const file of await collectMd(CONTENT_DIR)) {
  let text = await readFile(file, "utf8");
  const urlsBefore = text.split(OLD_PREFIX).length - 1;
  const altsBefore = (text.match(/!\[f:id:[^\]()\s]+\]\(\/hatena-images\/[^)\s]+[^)]*\)/g) ?? []).length;

  // 1) path 置換: 単純置換で url / plain link 両方を一括に扱う
  text = text.split(OLD_PREFIX).join(NEW_PREFIX);

  // 2) alt 空化: はてな記法の f:id が alt に来ている場合のみ ![ に対象を限定
  text = text.replace(/!\[f:id:[^\]()\s]*\]\((\/blog-images\/[^)\s]+)\)/g, (_match, url) => {
    altCleared += 1;
    return `![](${url})`;
  });

  if (urlsBefore > 0 || altsBefore > 0) {
    await writeFile(file, text);
    touched += 1;
    pathReplaced += urlsBefore;
  }
}

console.log(`files touched: ${touched}, path refs rewritten: ${pathReplaced}, alt cleared: ${altCleared}`);
```

### Task 5: rehype 寸法プラグイン (ビルド時 width/height 注入)

**Files:**

- Create: `src/markdown/rehype-image-size.ts`
- Modify: `astro.config.ts` (`markdown` に `rehypePlugins` 追加)

**Interfaces:**

- Consumes: Task 4 が置いた `/blog-images/` prefix と `public/blog-images/` 下の実体
- Produces: ビルド生成 HTML の `<img>` に width / height / decoding が付く。unified / hast の型依存はローカル定義にして新 dependency を積まない

- [ ] **Step 1: プラグイン本体を書く**

```ts
// src/markdown/rehype-image-size.ts
import path from "node:path";
import { stat } from "node:fs/promises";
import sharp from "sharp";

const IMAGE_URL_PREFIX = "/blog-images/";

// Why not: unified/hast 型の依存を追加しない。寸法注入だけが目的で、
// 依存の追加が得る利益がないから。
type HastNode = {
  type?: string;
  tagName?: string;
  properties?: Record<string, unknown>;
  children?: HastNode[];
};

async function dimensionsFor(src: unknown): Promise<{ width: number; height: number } | null> {
  if (typeof src !== "string" || !src.startsWith(IMAGE_URL_PREFIX)) return null;
  const clean = src.split("?")[0]!.split("#")[0]!;
  const file = path.resolve("public/blog-images", clean.slice(IMAGE_URL_PREFIX.length));
  // Why not: 並び替えや寸法不明な画像でビルドを落とさない。寸法がない
  // 画像は属性なしで出て、CLS には寄与しない (画像自体の表示には影響しない)。
  try {
    const info = await stat(file);
    if (!info.isFile()) return null;
    const meta = await sharp(file).metadata();
    return meta.width && meta.height ? { width: meta.width, height: meta.height } : null;
  } catch {
    return null;
  }
}

const walk = async (node: HastNode): Promise<void> => {
  if (node.tagName === "img") {
    const size = await dimensionsFor(node.properties?.src);
    if (node.properties && size) {
      node.properties.width = size.width;
      node.properties.height = size.height;
      node.properties.decoding = "async";
    }
  }
  for (const child of node.children ?? []) {
    await walk(child);
  }
};

export const rehypeImageSize = () => async (tree: unknown) => {
  await walk(tree as HastNode);
};
```
